## Known Limitation: Server-Side Stream Cancellation

### Issue
The current implementation only stops the **client-side stream consumption**. The server continues generating tokens from the upstream provider (OpenRouter) even after the user clicks stop.

### Root Cause
In `convex/http/aisdk.chat.ts`, the `streamText()` call does not receive an `abortSignal`:

```typescript
// Current implementation (line 90-93)
const result = streamText({
  model: provider(body.model),
  messages: await convertToModelMessages(chatMessages),
  // Missing: abortSignal: req.signal
});
```

### How the AI SDK Stop Works
1. The AI SDK's `stop()` function calls `AbortController.abort()`
2. This aborts the client-side fetch request
3. The browser closes the SSE/HTTP connection
4. **BUT** the server doesn't detect this and continues streaming from OpenRouter

### Recommended Fix
Pass the request's abort signal to `streamText`:

```typescript
const result = streamText({
  model: provider(body.model),
  messages: await convertToModelMessages(chatMessages),
  abortSignal: req.signal,  // <-- Add this
});
```

The standard `Request` object has a `.signal` property that triggers when the client disconnects. This should propagate through to the upstream OpenRouter request.
