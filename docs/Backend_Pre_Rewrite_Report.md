# Backend pre-rewrite handoff (source snapshot)

**Snapshot:** 2026-09-25, Git HEAD `892397f899e5b2ae9124ce886faf9f5ed625fce2`; the worktree was clean before this report. This is a **source-level inventory**, not an export of a running deployment or proof that the staged ownership backfill has run. Recheck source and deployment state before executing any migration. No credentials or production data are included.

## 1. Rewrite boundary and current behavior

Radium is a self-hosted BYOK project. `packages/backend` is the Convex application, its HTTP handlers, local logging component, and runtime-neutral helpers under `src/`. `apps/web` is the TanStack Start client and imports backend-generated function references, document IDs, and some shared source modules directly. The Agent Runner packages are health-check skeletons; Convex is not an execution sandbox for agent filesystem/command work. The root workspace uses Bun. The package scripts are `dev` (`convex dev`), `test` (Vitest), and `codegen` (`convex codegen`); do **not** invoke codegen modes that upload functions as part of inventory work. See [deployment](deployment.md) for the audited offline API-only binding command.

Implemented Gateway compatibility is **OpenAI-style Chat Completions and model listing**, not OpenAI Responses, Anthropic Messages, Gemini, or Grok protocols. Chatroom uses an AI SDK UI-message stream over a separate, session-authenticated HTTP endpoint, routing model calls through the same internal Gateway completion path (`convex/ai_gateway.ts` → `src/http/chat_completion.ts`). ChatGPT subscription integration adds its own browser-session routes and state; it is not general upstream pooling. Optional AI capture, best-effort operational logging, and usage estimates are distinct stores/purposes. New BYOK calls do not debit credits.

Primary reference files: `packages/backend/convex/schema.ts` (data and indexes), `convex/http.ts` (routes), `convex/workspaces.ts` and `src/workspaces/policy.ts` (authorization), `convex/migrations.ts` (staged backfill and verification), and `convex/secrets.ts` (secret names). Paths in this report are relative to `packages/backend/` unless otherwise specified. Existing [ownership](Radium_Gateway/Ownership.md), [telemetry](Radium_Gateway/Telemetry.md), [logging](logging.md), and [API](api.md) guides give more detail; source wins where a guide has an obsolete path or claim.

## 2. Persistence map: what must be accounted for

All tables below are in `convex/schema.ts` unless noted. Convex document IDs and `_creationTime` are referenced across tables and exposed in some client responses; preserve referential edges or explicitly translate them. Optional ownership fields are a migration state, not evidence that an old row belongs to an arbitrary workspace. Index definitions are in the schema; use them to plan bounded extraction and verification.

| Data                                                           | Current role and migration-sensitive edges                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `workspaces`, `workspace_members`                              | Personal owner is `ownerType: "user"` + Better Auth user ID. Owner is implicit; explicit membership is a `member` row keyed by workspace/user. `archivedAt` gates access. `legacyBalance`, `legacyOrganizationId`, `legacyTeamId` are bridge pointers; Better Auth organizations are **not** membership.                                                                                                                                                                                                                             |
| `workspace_configurations`, `workspace_credentials`            | Workspace/provider enablement, `active`, optional local provider `snapshot`, and deletion tombstone (`deletedAt`); one metadata row per workspace/provider with masked credential preview. A snapshot includes adapter npm name, endpoint (`api`), model mappings, supported parameters, and string pricing. Secret value lives in Secret Store. A tombstone prevents fallback resurrection.                                                                                                                                         |
| `providers`, `models`, `authors`                               | Global provider/model catalogue; `models.author` references `authors`. Local snapshots are authoritative when workspace configuration exists. Model slugs and provider slugs connect routing, listings, completion recording, and UI imports. Do not remove authors merely because standalone author queries look unused.                                                                                                                                                                                                            |
| `api_keys`; legacy `keys`, `balances`                          | New keys store `workspace`, name, SHA-512 hash, preview, optional revocation and `legacyKey` bridge. Key plaintext (`rad-sk-…`) is returned only at creation. Legacy `keys` store balance, hash, credit-era fields and revocation; `balances` contain credits and owner IDs. Legacy keys remain a live fallback. Revoking a mapped key must revoke **both** rows or a legacy fallback can revive it. Credit values are historical compatibility, not a new BYOK prerequisite.                                                        |
| `workspace_settings`; legacy `chatroom_settings`               | Workspace defaults (model/title model, chain-of-thought, telemetry controls, builtin tool-set IDs, MCP server IDs). Legacy defaults are user-scoped; migration picks one deterministic default owner workspace, not all of a user's workspaces.                                                                                                                                                                                                                                                                                      |
| `mcp_servers`, `subscription_state`                            | MCP server connection metadata has `userId`, optional workspace bridge, HTTP transport and none/bearer auth; bearer secret is external. Subscription state holds session and rate-limit values keyed by provider/namespace/key with optional expiry; preserve active login behavior or provide a controlled reauthentication path.                                                                                                                                                                                                   |
| `aisdk_chats`, `chat_completions`, `ai_apps`                   | Chats embed AI SDK message arrays, queued message, tool override, stream state, title/pin/interaction state; carry creator `userId`, optional workspace/scope and optional legacy balance. Completions store model ID, provider, BYOK/cancel/stream flags, token usage, estimated pricing, optional chat/user attribution and bill pointers to workspace/API key and/or balance/legacy key. `chat_completions` IDs also appear in the chat's `chat_completions` array and traces. `ai_apps` is an optional completion app reference. |
| `telemetry_traces`, `telemetry_spans`, `telemetry_payloads`    | Optional capture; traces carry workspace/API key, optional legacy attribution, actor, optional chat/completion references, correlation IDs, timings and flags. Spans reference trace; payloads reference trace/optional span and can contain raw input/output JSON when enabled. Treat payloads as sensitive content; do not migrate them into general logs.                                                                                                                                                                         |
| `components/logging/schema.ts:events`                          | **Isolated Convex component** table, not an app-schema table. Versioned envelope plus server-derived `actorId`/`receivedAt`. No retention or read/admin API is implemented.                                                                                                                                                                                                                                                                                                                                                          |
| Better Auth, migrations, Secret Store, rate limiter components | Mounted by `convex/convex.config.ts`; their component-owned records are outside the app schema. An app-table-only export is incomplete. Inventory component data and vendor-specific import/export capabilities before moving deployments.                                                                                                                                                                                                                                                                                           |

The message validator is `convex/aisdk_schemas.ts`; it admits AI SDK message parts and `v.any()` metadata/data. Preserve actual stored message shapes, not just an idealized text transcript. `src/workspaces/provider.ts` owns the provider snapshot/model validators; `convex/key.ts` owns persisted completion usage/pricing shapes; `src/telemetry/validators.ts` owns capture validators. There are no declared database-level foreign-key cascades: a rewrite needs an explicit policy for every retained/deleted reference and historical row.

### Secret Store mapping (never export plaintext into the report)

`convex/secrets.ts` defines the exact namespace/name combinations:

| Purpose    | Legacy namespace / name               | Workspace namespace / name                                   |
| ---------- | ------------------------------------- | ------------------------------------------------------------ |
| Provider   | `provider:<provider>` / `<balanceId>` | `workspace:<workspaceId>:provider:<provider>` / `<provider>` |
| Exa        | `balance:<balanceId>:tools` / `exa`   | `workspace:<workspaceId>:tools` / `exa`                      |
| MCP bearer | `mcp:<serverId>` / `bearer`           | `workspace:<workspaceId>:mcp:<serverId>` / `bearer`          |

Secret Store metadata includes type and masked preview; `workspace_credentials` is metadata, not the secret. A missing secret may be legitimately absent; expired or unavailable encryption keys block verified migration. Preserve write-only display behavior and key material availability while migrating. ChatGPT subscription session-cookie credentials are stored through the provider secret path; `subscription_state` also holds login/rate-limit state. Consult `convex/providers.ts`, `convex/aisdk_tools.ts`, and `src/subscriptions/chatgpt.ts` before changing their lifecycle.

## 3. Authorization and externally visible contracts

- **Browser session:** Better Auth in `convex/auth.ts`/`auth.config.ts`, with app auth entry in `apps/web/src/app/api/auth/$.ts`. Browser-facing functions call `authComponent.getAuthUser(ctx)`; user IDs are Better Auth IDs, not a caller-provided workspace claim. `requireOwnedWorkspace` gates owner settings, providers, credentials, keys, MCP and telemetry management. `requireWorkspaceAccess` admits owner or direct member to models and eligible chats. Owner access does **not** override another creator's personal-chat privacy. `scope` defaults to `personal` for legacy chats. Chat creator controls scope; `convex/chatroom.ts` determines other chat management rights.
- **Gateway API key:** `convex/key.ts:getKeyInfo` hashes the bearer key, looks in `api_keys`, then legacy `keys`; rejects revoked or inconsistent mappings. HTTP endpoints resolve/create legacy workspace mapping if necessary. A key authenticates a workspace, not a browser user/member. `convex/keys.ts` creates, lists, renames and revokes keys (including dual revocation for migrated keys). Never use browser-session authorization as a substitute for key auth.
- **HTTP site routes (`convex/http.ts`):** `POST /api/openai/v1/chat/completions` (JSON or SSE `data: …`, ending `[DONE]`), `GET /api/openai/v1/models` (both bearer-auth); `POST`/`OPTIONS /api/aisdk/chat` (Better Auth session and chat access, AI SDK UI stream); `GET`/`POST`/`OPTIONS` prefix `/api/subscription/chatgpt-subscription/` (Hono owner/session integration, device login/status/logout/proxy as handled by dependency); Better Auth component registers its own routes. These are on the Convex site origin, not the Vite API origin. The web app has a generic `/api/backend/*` forwarding route at `apps/web/src/app/api/backend/$.ts`; see [subscription routing](Radium_Gateway/Subscriptions.md).
- **Completion path:** `src/http/chat_completion.ts` parses `src/types/openai/types.ts`, resolves key/workspace, calls `src/ai_balancer.ts` → internal `providers.resolveProviderCandidatesForModel` → `src/providers.ts` adapter/`src/translators/openai.ts`. The balancer selects a **random** candidate and reads workspace (or legacy) credentials. No pool health, scheduling, cooldown, safe failover or general upstream-instance model exists. A callback writes `chat_completions` via `key.recordCompletion` with estimated cost. Chatroom `src/http/aisdk.chat.ts` runs AI SDK `streamText`, calls the internal Gateway provider, persists chat messages at end, resolves Exa search/MCP tools, and creates optional telemetry. Streaming/abort/error and recording behavior should be tested before swapping the runtime; do not assume retries are safe after stream output.
- **Client function surface:** `apps/web` invokes `workspaces` (list/ensure/create/rename/icon/member/archive/restore), `providers` (list/import/enable/models/credentials/delete), `keys` (list/create/delete), `models.availableModels`, `aisdk` (create/fork/get/list/scope/title/pin/delete), `chatroom` defaults/tools, `mcp` CRUD, `exa` key operations, `logs` activity/generations, `telemetry` settings/traces/summary, `auth.userInfo`, and `logging.ingest`. Other registered functions such as `usage.getUsage` and `telemetry.deleteTrace` exist but were not found in direct web calls during this inventory. Search `api.<module>.<function>` in `apps/web/src` for the exact active callers; generated `backend/convex/_generated/api` and `dataModel` IDs are imported widely. Maintain a compatibility adapter or update callers together with their response shapes and auth behavior.

Other existing public Convex exports (e.g. `authors`, `models.modelInfo`, `key.getKeyInfo`) may have external callers not visible in this repository. Inventory actual deployment consumers before removing registered functions. `convex/aisdk.ts` schedules `chatroom.generateForChat` (formerly `chat_titles.generateForChat`); internal functions are also cross-file contracts, not browser APIs.

## 4. Existing ownership bridge: migration, not completed rollout

`convex/migrations.ts` uses `@convex-dev/migrations` and defines `runAll` in this order: `workspacesFromBalances`, `workspacesFromSettings`, `mcpServersToWorkspaces`, `workspaceConfigurations`, `workspaceCredentials`, `apiKeysFromKeys`, `chatroomSettingsToWorkspaces`, `chatsToWorkspaces`, `completionsToWorkspaces`, `tracesToWorkspaces`, `spansToWorkspaces`. It copies (does not delete) legacy keys and secret namespaces and backfills chat scope as personal. Configuration and credential migration check mapping uniqueness, owner consistency and secret-read results; bad edges fail closed rather than being silently reassigned. Existing runtime fallback is bounded but still live: when a legacy workspace has **no** local configuration rows, enabled global catalogue providers may be used; any local row, disabled or tombstoned, ends that fallback. `convex/provider_records.ts` and `convex/providers.ts` implement it.

Internal paginated checks are `verifyBalances`, `verifyWorkspaces`, `verifyWorkspaceConfigurations`, `verifyProviderConfigurations`, `verifyWorkspaceCredentials`, `verifyProviderSecrets`, `verifyKeys`, `verifyApiKeys`, `verifyWorkspaceSettings`, `verifyMcpServers`, `verifyChatroomSettings`, `verifyChats`, `verifyCompletions`, `verifyTraces`, `verifySpans`, `verifyTelemetryPayloads`. Each page returns counts, `continueCursor`, `isDone`, `pageClean`, issue codes and bounded sample IDs. Exhaust **every page of every applicable verifier**, aggregate issues and require zero before narrowing. `verifyProviderSecrets` supports a provider filter for transaction limits. Neither `runAll` nor these verifiers has been run against a deployment as part of this report; the existing guide also records no deployment rollout verification. Do not trigger a remote migration without explicit approval.

New workspace-only writes mean the old required balance schema is not a rollback target. Establish a forward-only widen → backfill → verify → switch reads/writes → narrow plan for the replacement, with deployment-specific counts and backups. Identity and data mapping to settle _before_ copying: Better Auth users/sessions, workspace IDs and membership, legacy balance-to-workspace bijection, key hashes/revocations, provider snapshots and model slugs, settings/MCP edges, chat privacy/creator, completion and trace attribution, component-owned secrets/session state. For a different datastore, maintain a durable old-ID → new-ID mapping and check every cross-table edge; do not invent missing ownership from a nullable field. Freeze or dual-write with explicit ordering/idempotency during cutover so new chats, revocations and credentials cannot diverge mid-export.

## 5. Operational dependencies, gaps and verification

Runtime configuration is read from `SITE_URL` (auth origin/CORS), `SECRET_STORE_KEYS` (component encryption), `LWC_SECRET` (ChatGPT subscription), `AISDK_MaxRetries` (translator; default 0), and optional `OTEL_EXPORTER_OTLP_*`/`OTEL_SERVICE_NAME` (export). The web uses `VITE_CONVEX_URL`, `VITE_CONVEX_SITE_URL` and deployment-specific configuration; verify owning env examples and [deployment guide](deployment.md) without printing actual values. External calls include configured AI provider endpoints, Exa, user-configured MCP HTTP endpoints and optional OTLP export. Configured local/private upstreams are a supported self-hosted case; comprehensive SSRF/egress policy is not implemented.

Known rewrite risks: routing is random and one provider credential per provider/workspace, not an account/server pool; provider/model reads and keys have fixed bounds (e.g. 200); archive does not inspect all child resources; message arrays and optional raw telemetry payloads can grow; capture has no automatic retention or durable finalization retry; operational logging component has no pruning; author references still serve model listings/imports; Chatroom stream cleanup/state on every failure path is not guaranteed by the schema. These are observations and migration design inputs, not a claim that a new architecture already exists. Consult [upstream instances](tasks/04_Upstream_Instances.md), [load balancing](tasks/05_Gateway_Load_Balancer.md), [Runner](tasks/06_Chatroom_Runner.md), and [workspace operations](tasks/09_Workspace_Operations.md) for unimplemented proposals.

**Checks for the successor:** first record the deployment ID/environment privately, schema/component versions, row counts per table, actual migration status, Secret Store key availability, and whether old credentials or sessions need preservation. Build a table-by-table field/ID map plus auth/privacy assertions. Exercise at least: owner/member/personal/shared chat isolation; workspace selection; legacy and new key acceptance and revocation; provider deletion tombstone and model listing/routing; JSON and streaming completions with usage linkage; Chatroom tool/stream persistence; opt-in telemetry capture and owner-only reads. Use `bun run test` for the existing backend suite, `bun run --cwd apps/web vite:build` for client compatibility, and scoped lint/checks as needed. Source-level tests are **not** deployment migration verification. No tests, migrations, uploads, deployments or remote writes were performed to produce this report.
